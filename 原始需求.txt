# Windows 桌面软件开发需求：随声输入

你是一名资深 Windows 桌面软件工程师、产品经理和交互设计师。请帮我开发一款名为「随声输入」的 Windows 桌面语音输入软件。

我要的是可以安装、运行和实际使用的软件，不是只有界面、静态演示、模拟数据或技术方案。

请按照以下完整要求，完成产品设计、程序开发、测试和安装打包。

---

## 一、软件定位与核心目标

开发一款适用于 Windows 10/11 的桌面软件，让用户在其他软件的文字输入框中放好光标后，通过自定义全局快捷键或桌面悬浮球启动录音，将语音转换为文字，并写入原来的输入位置。

软件还必须提供一个可选的「AI 提示词优化」模块，通过用户配置的外部 AI API，将语音识别结果或手动输入的文字优化为更清晰的提示词。

软件应具备正常桌面软件应有的设置、托盘、开机自启动、安装卸载、异常提示和隐私保护能力。

### 兼容场景

尽量兼容：

- 浏览器搜索框。
- 网页表单和在线编辑器。
- 微信、QQ、钉钉、飞书等聊天软件。
- Word、记事本等文档编辑软件。
- VS Code 等代码编辑器。
- 其他标准 Windows 文本输入控件。

不得宣称百分之百兼容所有输入框。

对于受权限限制、禁止粘贴或使用特殊控件的应用，需要明确说明限制，并提供复制识别结果、手动粘贴等备用方式。

---

## 二、核心使用流程

### 1. 普通语音输入流程

1. 用户在目标软件的输入框中放好光标。
2. 按下全局快捷键，或者左键单击悬浮球。
3. 软件记录目标窗口及必要的输入焦点信息。
4. 开始录音，悬浮球显示明确的录音状态。
5. 用户说话，界面显示音量变化和录音时长。
6. 再次按快捷键或点击悬浮球，停止录音。
7. 软件进行语音识别及用户启用的基础文字处理。
8. 验证原目标窗口和输入位置。
9. 将文字插入原输入位置。
10. 输入成功后恢复待机。

失败时保留本次结果，允许复制、重试或手动处理。

默认采用“停止录音后一次性写入”的可靠模式。

实时识别预览可以作为增强功能，但不得把分段识别伪装成真正的流式识别。

### 2. 开启 AI 提示词优化后的流程

录音
→ 语音识别
→ 基础文字处理
→ 调用外部 AI 优化
→ 预览、编辑或确认
→ 验证输入目标
→ 写入目标输入框。

AI 优化默认需要用户预览确认，不得未经确认直接覆盖原文或输入到其他软件。

可提供“优化完成后自动写入”选项，但默认关闭，并说明开启后的行为。

### 3. 基础交互原则

- 软件启动后只能进入待机，不能自动录音。
- 开机自启动后不能自动录音。
- 悬浮球和状态展示默认不抢夺输入焦点。
- 不自动发送聊天消息。
- 不自动提交网页表单。
- 不自动执行终端命令。
- 用户取消任务后，不得再写入该任务的任何结果。
- 用户切换输入目标后，不能猜测位置并继续自动写入。

## 三、录音与语音识别功能

### 1. 录音模式

至少提供两种模式：

#### 切换模式

按一次快捷键开始录音，再按一次结束录音。

#### 按住说话模式

按住快捷键录音，松开后结束录音并进行识别。

悬浮球左键单击默认采用开始／停止的切换操作，不要求用户长时间按住鼠标。

### 2. 录音控制

提供：

- 主界面开始录音按钮。
- 停止录音按钮。
- 取消当前任务按钮。
- 快捷键操作。
- 悬浮球操作。
- 可配置的最长录音时长。
- 可选的静音自动结束功能。
- 可配置的静音等待时间。

录音期间可按 Esc 取消本次任务，但只能在本软件任务激活期间处理，不应常驻拦截其他应用的 Esc。

正确处理长按、连按、按键重复和重复点击，避免重复录音、重复识别或重复输入。

### 3. 麦克风设置

提供：

- 麦克风设备选择。
- 输入音量指示。
- 麦克风测试。
- 当前设备状态。
- 设备不可用时的明确提示。

处理以下情况：

- 没有麦克风。
- 系统麦克风权限关闭。
- 设备被拔出。
- 设备被其他程序独占。
- 录音过程中设备变化。
- 没有检测到有效语音。

界面不得因此卡死或崩溃。

### 4. 识别能力

至少支持：

- 普通话。
- 英语。
- 中英文混合输入。
- 自动标点。
- 常见数字、日期、时间和金额表达。

提供识别语言设置。

识别质量应依据实际使用的模型说明，不得夸大准确率。

### 5. 基础文字处理

提供可配置选项：

- 保留原始识别结果。
- 自动标点。
- 基础排版。
- 可选的口语词清理。
- 自定义词语替换表。

口语词清理默认关闭，避免改变用户原意。

词语替换表用于修正人名、公司名和专业术语。

如果识别引擎不支持真正的热词增强，不得把识别后的文本替换包装成“模型热词识别”。

### 6. 语音指令

提供可关闭的基础指令模式，例如：

- “换行”。
- “新段落”。

普通文字听写与指令识别必须有明确规则，避免用户正常说出这些词语时被意外执行。

换行不能简单地在所有软件中模拟 Enter，因为 Enter 在某些软件中会发送消息或执行命令。

无法安全插入换行时，保留结果并提示用户手动处理。

## 四、自定义全局快捷键

提供独立的快捷键设置页面。

### 功能要求

- 支持录制新的快捷键组合。
- 支持 Ctrl、Alt、Shift、Win 与普通按键的合理组合。
- 设置后立即生效。
- 明确显示当前快捷键和当前录音模式。
- 支持恢复默认快捷键。
- 修改失败时保留原来的有效配置。
- 暂停快捷键后，不响应录音热键。
- 恢复后能够正常使用。

默认快捷键可以选择 Ctrl + Alt + Space，但必须以实际注册成功为准。

### 冲突与边界处理

- 检测能够检测到的快捷键占用冲突。
- 注册失败时明确提示用户更换。
- 避免系统保留或容易误触的组合。
- 正确处理按键重复、长按、快速连按。
- 正确处理系统休眠和唤醒后的快捷键状态。

快捷键监听只能服务于本软件功能，不得记录用户的普通键盘输入。

## 五、跨软件文字写入

这是软件的核心能力，必须优先保证可靠性。

### 1. 输入目标管理

- 开始录音时记录目标窗口和必要的输入焦点信息。
- 悬浮球启动录音时，不得把悬浮球自身当作输入目标。
- 不得因为显示状态条而改变原来的输入位置。
- 写入前检查目标窗口是否仍然有效。
- 尽可能确认目标输入控件仍然可用。
- 用户切换到其他输入目标时，暂停自动写入，要求确认或重新选择。
- 原窗口关闭、输入控件失效或无法确定光标位置时，保留结果并提供复制。

打开本软件预览面板造成的焦点变化，与用户切换到其他外部输入目标应区别处理；恢复原目标前仍必须验证，不能盲目模拟点击。

### 2. 写入方式

根据控件和应用实际情况，选择适合 Windows 的文本写入方法，并提供兼容性回退。

可以结合：

- Windows UI Automation。
- Unicode 输入。
- 剪贴板粘贴。

不得只依赖固定延时的模拟按键。

应尽量保留目标应用正常的：

- 光标插入语义。
- 选中文字替换语义。
- 撤销语义。

不得擅自覆盖整个输入框或整篇文档。

### 3. 剪贴板保护

涉及剪贴板时：

- 尽量保留并恢复原有内容。
- 如果用户期间复制了新内容，不得用旧备份覆盖新内容。
- 不把完整剪贴板内容持久化到磁盘。
- 粘贴失败时保留识别结果。
- 提供“复制文字”按钮。

### 4. 安全限制

- 对可识别的密码框和安全输入控件，默认禁止自动写入。
- 不承诺能够识别所有软件中的密码框。
- 不尝试向锁屏、UAC 安全桌面等系统安全界面写入。
- 普通权限程序无法向某些管理员权限应用输入时，应解释原因。
- 不得默认长期以管理员身份运行。
- 不得通过绕过系统安全限制来实现输入。

## 六、常驻置顶悬浮球

悬浮球是软件必须交付的主要操作入口，不是可有可无的装饰功能。

### 1. 常驻与置顶

要求：

- 软件运行时默认显示悬浮球。
- 主面板关闭或最小化后，悬浮球仍然可见。
- 在普通 Windows 桌面应用环境中保持置顶。
- 切换其他软件后仍尽量可见。
- 开机自启动后显示悬浮球并进入待机。
- 悬浮球自身不在任务栏中显示独立按钮。
- 待机时不抢夺键盘焦点。
- 不影响用户正常操作其他软件。
- 不因待机自动变得完全透明。
- 默认不自动隐藏到屏幕边缘。

“始终置顶”仅适用于正常桌面环境。

锁屏、UAC 安全桌面、独占全屏和其他置顶窗口可能造成例外，必须如实说明，不能承诺在任何情况下都绝对可见。

不得通过提高管理员权限或绕过系统安全机制强行置顶。

### 2. 鼠标操作

支持：

- 左键单击：开始或停止语音输入。
- 左键按住拖动：移动悬浮球。
- 右键单击：打开快捷菜单。

必须正确区分点击和拖动。

拖动结束后，不能误触发录音。

点击悬浮球开始录音时，不得导致原文字输入位置丢失。

### 3. 右键菜单

至少包含：

- 打开软件主面板。
- 开始／停止语音输入。
- 取消当前任务，仅在存在任务时可用。
- 开启／关闭 AI 提示词优化。
- 打开 AI 提示词设置。
- 更换悬浮球形象。
- 打开软件设置。
- 暂停／恢复全局快捷键。
- 重置悬浮球位置。
- 退出软件。

菜单选项应与当前状态一致，例如未录音时显示“开始录音”，录音时显示“停止录音”。

### 4. 位置与显示设置

提供：

- 拖动后自动记忆位置。
- 重启后恢复上次位置。
- 多显示器支持。
- 高 DPI 和不同系统缩放比例适配。
- 可选的屏幕边缘吸附。
- 大小调节。
- 透明度调节。
- 合理的最小尺寸和透明度限制。

不得允许用户把悬浮球设置得完全不可见或无法点击。

当显示器断开、分辨率变化或历史位置失效时，自动将悬浮球调整到当前可见屏幕范围内。

### 5. 自定义悬浮球形象

提供独立的“悬浮球外观”设置区域。

至少支持：

- 多种内置形象。
- 用户导入本地 PNG、JPEG 等静态图片。
- PNG 透明背景。
- 图片预览。
- 缩放。
- 裁剪。
- 图片位置调整。
- 切换后立即生效。
- 恢复默认形象。

导入后，将图片保存到软件自己的用户数据目录，避免原图片移动或删除后形象失效。

对图片格式、文件大小和像素尺寸进行合理限制。

图片解析失败时，保留原有形象并提示，不得导致软件崩溃。

动态 GIF 或其他动画形象可以作为增强功能，但必须真正实现并测试后，才能标记为支持。

### 6. 状态反馈

无论用户选择什么图片，都必须通过外圈、角标、动画或独立状态标识，明确区分：

- 待机。
- 正在录音。
- 正在语音识别。
- 正在进行 AI 优化。
- 正在写入。
- 等待用户确认。
- 发生错误。
- 快捷键已暂停。

录音状态不能只依赖颜色区分，还必须提供清晰的图标、动画或文字提示。

自定义图片不能遮挡必要的录音和错误状态标识。

### 7. 与悬浮状态条的关系

悬浮球作为常驻入口。

原有小型悬浮状态条作为可选的任务详情展示，用于显示：

- 录音时长。
- 音量变化。
- 识别或优化进度。
- 停止和取消操作。

状态条应小巧、可拖动、尽量不遮挡输入区域，默认不抢焦点，并记忆位置。

关闭状态条不等于关闭悬浮球，也不能让录音过程失去明确可见的状态提示。

## 七、语音识别引擎

设计清晰的识别引擎接口，但不要过度抽象。

### 1. 本地离线识别

优先提供一个真正可运行的离线识别方案。

要求：

- 使用适合 Windows 分发的成熟识别库和模型。
- 支持首次模型下载。
- 显示下载进度。
- 支持失败重试。
- 支持设置模型目录。
- 提示模型大小、磁盘需求及大致性能取舍。
- 下载完成后进行完整性校验。
- 模型未准备好时，不允许假装可以识别。
- CPU 模式必须可用。
- GPU 加速可以作为可选增强。
- 模型加载和推理不能阻塞界面。

第一阶段允许只完成一个真实可用的离线引擎，优先打通完整使用流程。

### 2. 云端语音识别

作为后续可选增强：

- 用户自行选择服务。
- 用户填写自己的 API Key。
- 提供连接测试。
- 提供超时、取消和错误提示。
- 首次使用前说明音频将发送给所选服务。
- 只有实际接入和测试过的服务，才能标记为支持。
- 不得在离线识别失败后，未经用户同意自动上传云端。

API Key 使用 Windows 凭据管理器或 DPAPI 等机制保护，不得明文写入普通配置和日志。

### 3. 区分两个云端功能

“云端语音识别”与“外部 AI 提示词优化”是不同功能：

- 云端语音识别处理音频。
- AI 提示词优化处理文字及优化指令。

两者必须分别配置、分别开关、分别说明数据发送范围。

---

## 八、AI 提示词优化模块

这是最终必须交付的功能，但用户可以自行选择开启或关闭，默认关闭。

### 1. 功能定位

通过用户配置的外部 AI API，将以下内容优化为更清晰、完整、便于 AI 理解和执行的提示词：

- 语音识别得到的文字。
- 用户手动输入的文字。
- 用户粘贴的已有提示词。

必须同时支持：

1. 用 AI 优化用户的提示词。
2. 用户修改控制优化行为的指令和模板。

不能只提供一个不可修改的固定优化按钮。

### 2. 开关与状态同步

提供全局开关：

- 主面板可以开启和关闭。
- 设置页面可以开启和关闭。
- 悬浮球右键菜单可以快捷切换。

要求：

- 各入口之间状态实时同步。
- 保存用户选择，下次启动恢复。
- 默认关闭。
- 没有配置 API 时，普通语音输入仍然正常工作。
- 只有启用功能、完成有效配置并取得必要的数据发送确认后，才允许发送优化请求。

关闭时：

录音 → 语音识别 → 基础文字处理 → 写入目标输入框。

开启时：

录音 → 语音识别 → 基础文字处理 → 外部 AI 优化 → 预览或确认 → 写入目标输入框。

关闭功能后不得发送优化请求。

处理中关闭功能，应取消当前优化任务，并忽略迟到的返回结果，不得误写入。

### 3. API 配置

提供独立配置页面，至少包含：

- 服务名称。
- API 接口地址。
- API Key。
- 模型名称。
- 请求超时时间。
- 最大输出长度，仅在服务支持时显示相应参数。
- 测试连接按钮。
- 保存配置按钮。

优先实际支持一种明确协议，例如经过验证的 OpenAI 兼容接口。

不能假设所有自称兼容的服务，其请求格式和能力都完全相同。

要求：

- 调用真实接口，不得使用模拟结果。
- 不编造接口地址。
- 不编造模型名称。
- 不编造兼容性说明。
- 公网服务使用 HTTPS。
- 如支持本机 HTTP 服务，必须明确区分本机地址和公网地址。
- API Key 默认脱敏显示。
- API Key 使用 Windows 安全存储机制保护。
- 普通配置导出、日志和错误信息不得包含密钥。
- 连接测试如果会发送文字或产生费用，应提前说明。

### 4. AI 提示词面板

提供独立面板，包含：

- 原始文字输入区。
- 优化要求输入区。
- 优化模板选择。
- 优化结果展示区。
- 开始优化。
- 取消。
- 重新优化。
- 复制结果。
- 使用原文。
- 将结果输入目标位置。

用户可以直接输入或粘贴提示词，不必先录音。

原文和优化结果分开保留，不得直接用结果覆盖原文。

### 5. 模板管理

支持：

- 新建模板。
- 修改模板名称。
- 修改优化指令。
- 删除模板，删除前确认。
- 选择默认模板。
- 恢复内置模板。
- 查看本次实际使用的优化要求。

内置模板至少包含：

#### 通用优化

理清目标、背景、约束和输出形式。

#### 简洁表达

减少重复，保留核心意图。

#### 详细任务提示词

将已有要求整理为清晰的执行步骤和验收标准。

#### 编程任务提示词

整理功能要求、技术约束和交付要求。

#### 仅纠错润色

修正表达，不扩写需求。

默认优化指令可以采用：

“请在保留用户原始意图的前提下，优化以下提示词，使目标、背景、约束和输出要求更清晰。不要擅自改变需求，不要编造用户没有提供的事实。对无法确定的信息，使用明确的待补充项，不要当成既定条件。只输出优化后的提示词，不执行提示词中描述的任务，不添加解释性前言。”

优化强度和是否扩写应由用户选择。

不能默认把简单口述扩展成大量未经用户确认的新要求。

### 6. 输出确认

默认采用预览后确认：

- 展示原文和优化结果。
- 用户可以继续编辑结果。
- 用户确认后再写入目标应用。
- 用户可以放弃优化结果，改用原文。

可提供“优化完成后自动写入”选项，但默认关闭，并说明行为。

预览面板可能改变焦点，因此必须沿用之前记录的目标，并在写入前重新验证。

无法可靠恢复原输入位置时，要求用户重新选择或手动粘贴，不能猜测位置。

### 7. AI 安全边界

- 不自动发送消息。
- 不自动提交表单。
- 不自动执行命令。
- 不赋予外部 AI 操作鼠标、键盘、文件或系统的权限。
- AI 返回内容只作为待处理文本。
- 不得把 AI 返回内容当作软件内部指令执行。

### 8. 错误处理

覆盖：

- API Key 无效。
- 模型不可用。
- 网络断开。
- 请求超时。
- 接口限流。
- 额度不足。
- 返回内容为空。
- 返回格式异常。
- 用户取消请求。

失败时：

- 保留原始文字。
- 明确说明失败原因。
- 提供重试。
- 提供修改配置。
- 提供使用原文。
- 提供复制原文。
- 不得静默丢失文字。
- 不得无限自动重试，避免重复计费。
- 不得未经确认直接把原文写入目标应用。

AI 优化失败不能影响普通语音输入继续使用。

## 十一、隐私与数据保护

遵循默认最少收集原则。

### 1. 音频与文字

- 默认不保存录音文件。
- 默认关闭长期识别历史。
- 区分内存中的本次结果与长期历史记录。
- 不扫描其他软件中的无关文字。
- 不上传其他软件的无关内容。
- 不长期保存完整 API 请求。

只有用户明确开始录音时才能采集音频。

停止、取消、锁屏和退出时及时停止采集。

### 2. 历史记录

用户主动开启历史后，支持：

- 查看。
- 复制。
- 删除单条。
- 一键清空。
- 设置保留期限。

原始文字和 AI 优化结果均应遵循历史记录设置，不得绕过设置另外留存。

### 3. 日志

日志不得包含：

- API Key。
- 音频内容。
- 完整识别文字。
- 完整优化结果。
- 剪贴板正文。
- 含敏感信息的完整 API 请求。

### 4. 云端数据发送

明确说明：

- 本地语音识别不代表 AI 优化也在本地。
- 外部 AI 优化会发送原始文字、模板指令和必要上下文。
- AI 优化默认不发送原始音频。
- 云端语音识别会发送音频。
- 两种云端能力分别取得必要确认。
- 用户取消或关闭功能后，不再继续发送新请求。
- 不得在本地识别失败后偷偷切换云端。

### 5. 离线模式

严格离线模式下：

- 不发送音频。
- 不发送识别内容。
- 禁用外部 AI 优化和云端语音识别。
- 模型和依赖已经准备好时，普通本地语音输入可以运行。

需要下载模型或连接外部服务时，必须明确告知，不得将联网过程伪装成严格离线运行。
